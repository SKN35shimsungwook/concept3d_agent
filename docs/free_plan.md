# 무료 운영 계획: 비용 0원으로 시중 서비스급 결과 내기

> 상태: **계획 단계**입니다. 아래 내용은 아직 구현되지 않았습니다.
> 사실 확인일: 2026-09-25. 무료 한도와 모델 제공 여부는 자주 바뀌니 구현 전에 다시 확인하세요.

## 결론

| 질문 | 답 |
|---|---|
| 결과물 **품질**을 시중 서비스 수준으로 올릴 수 있나? | **대부분 가능.** 오픈소스 TRELLIS.2(MIT, PBR 재질 지원)로 모델을 바꾸고, 입력 정리와 후처리를 붙이면 됨 |
| **속도와 처리량**도 같아질 수 있나? | **무료로는 불가.** 무료 계정의 HF GPU는 하루 5분이라 **하루 몇 건 수준**. 데모와 포트폴리오에는 충분하지만 서비스 규모는 안 됨 |
| 체감 성능 차이는 어디서 오나? | 모델만의 문제가 아님. 입력 정리, 여러 후보 중 선택, 후처리, UX 같은 **파이프라인 차이가 큼**. 이 부분은 전부 무료로 따라잡을 수 있음 |

## 확인된 사실

| 사실 | 이 프로젝트에 주는 영향 | 출처 |
|---|---|---|
| `gemini-2.5-flash-image`(나노 바나나)가 **2026-10-02 종료 예정** | 현재 정제 단계 기본값이 곧 동작하지 않음. 후속 모델은 `gemini-3.1-flash-image`(나노 바나나 2) | [Gemini 가격 페이지](https://ai.google.dev/gemini-api/docs/pricing) |
| Gemini **이미지 모델은 API 무료 티어가 없음** | 정제 단계는 지금도 유료. 무료 운영에서는 제외 | 같은 페이지 |
| `gemini-2.5-flash` 텍스트 모델은 무료 티어 있음 | 컨셉 분석과 에이전트 판단은 계속 무료로 가능 (요청 수 제한 있음) | 같은 페이지 |
| HF ZeroGPU 하루 한도: 비로그인 **2분**, 무료 계정 **5분**, PRO **40분** | `HF_TOKEN`만 넣어도 한도가 2.5배로 늘어남 | [ZeroGPU 문서](https://huggingface.co/docs/hub/spaces-zerogpu) |
| **무료 계정도 ZeroGPU Space를 2개까지 직접 호스팅** 가능 (이메일 인증, 가입 30일 이상). GPU는 48GB | RunPod 없이 **우리 모델을 올린 전용 GPU 서버를 무료로** 가질 수 있음 | 같은 문서 |
| TRELLIS.2: **MIT 라이선스**, 24GB 이상 필요, PBR 재질(투명도 포함), 최대 1536³ 해상도 | 지금 쓰는 TRELLIS v1보다 품질이 좋고 상업적으로 써도 됨. 공개 Space `microsoft/TRELLIS.2`가 있음 | [모델 카드](https://huggingface.co/microsoft/TRELLIS.2-4B) |

## 시중 서비스와의 차이와 무료로 따라잡는 방법

| 요소 | 시중 서비스 (Tripo, Meshy 등) | 현재 코드 | 무료로 따라잡는 방법 |
|---|---|---|---|
| 3D 모델 품질 | 자체 대형 모델 | TRELLIS v1 | **TRELLIS.2로 교체** |
| 입력 정리 | 자동 배경 제거와 크롭 | 흰 배경 패딩만. 정제는 유료 API | 로컬 CPU에서 **`rembg` 배경 제거 + 피사체 자동 크롭과 중앙 정렬** |
| 여러 후보 | 여러 개 생성 후 사용자가 선택 | 1개만 생성 | seed를 바꿔 추가 생성. 무료 Gemini가 원본과 비교해 가장 나은 것을 추천. **한도를 쓰므로 사용자가 원할 때만** |
| 후처리 | 리토폴로지, 크기 정규화, 폴리곤 수 옵션 | 재질 보정만 | `trimesh`로 중심·크기 정규화, 바닥 정렬, 폴리곤 줄이기. 필요하면 **Blender 헤드리스(무료, CPU)**로 리메시와 턴테이블 렌더 |
| 스타일 변환 (픽사풍, 클레이 등) | 프리셋 버튼 | 유료 Gemini 이미지 모델 | 자체 ZeroGPU Space에 **FLUX.1-schnell 또는 SDXL + IP-Adapter**. 나중에 LoRA로 우리 스타일 추가 |
| 속도와 대기열 | 전용 GPU | 공용 Space 대기열 | 자체 ZeroGPU Space + `HF_TOKEN` 로그인으로 우선순위를 올림. **같은 이미지는 캐시**해서 중복 호출 제거 |
| 안정성 | 서비스 수준 보장 | 공용 Space 하나에 의존 | **대체 경로 순서:** 자체 Space → `microsoft/TRELLIS.2` → `trellis-community/TRELLIS` |
| UX | 진행률, 기록, 비교, 재생성 | 기본 기능만 | 단계별 진행 표시, 원본과 3D 비교, 기록 영구 저장, seed 재생성 버튼, 내보내기 형식 선택 |

## 무료 자원 배치

| 역할 | 자원 | 무료 한도 |
|---|---|---|
| 컨셉 분석, 에이전트 판단, 결과 채점 | Gemini 2.5 Flash 무료 티어 | 분당·일일 요청 수 제한 |
| 3D 생성 | 자체 ZeroGPU Space #1 (TRELLIS.2) | 호출한 계정 기준 하루 5분 (구현 때 차감 기준 확인 필요) |
| 스타일 변환 | 자체 ZeroGPU Space #2 (FLUX.1-schnell 또는 SDXL + IP-Adapter) | 위 5분을 같이 사용 |
| 배경 제거, 후처리 | 로컬 CPU (`rembg`, `trimesh`, Blender) | 제한 없음 |
| LoRA 학습 | Kaggle Notebook 무료 GPU 또는 Colab 무료 | 학습에만 사용. **Colab 무료 약관은 원격 UI나 서버 용도를 제한**하므로 추론 서버로는 쓰지 않음 |
| 모델 가중치 저장 | Hugging Face Hub | 무료 |

### 하루 처리량 추정

- 하루 5분 = 300초
- TRELLIS v1 실측은 약 31초였습니다. TRELLIS.2는 해상도에 따라 더 걸릴 수 있어서 **1건에 30~60초로 가정**합니다. 실제 값은 측정이 필요합니다.
- 스타일 변환을 켜면 1건에 5~10초가 더 듭니다.
- → **하루 약 4~9건.** 그래서 기본은 후보 1개만 만들고, "다른 버전 보기"는 사용자가 누를 때만 실행합니다.

## 로드맵 (전 단계 비용 0원)

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| **0. 긴급 대응** | 정제 기본값을 `off`로 변경. `REFINE_BACKEND=off\|rembg\|gemini\|space` 분기 추가. `gemini`를 고른 경우의 기본 모델을 `gemini-3.1-flash-image`로 교체 | 10월 2일 이후에도 Gemini 키 하나로 전체 파이프라인이 동작 |
| **0-b. 토큰 절약** | 고정 순서를 MCP 도구 `concept_to_3d` 하나로 묶기, `modeler`에 `include_contents='none'`, 분석용 384px 썸네일, 결과 캐시. 자세한 내용은 [README의 토큰 사용량 섹션](../README.md#토큰-사용량-문제와-해결-과정) | 1회 실행에 LLM 호출 3회 이하, 이미지 전송 1회 |
| **1. 입력 품질** | `rembg` 배경 제거 + 피사체 자동 크롭과 중앙 정렬을 `prepare_image`에 추가 | 배경이 복잡한 사진도 3D 결과에 배경 잔해가 없음 |
| **2. 3D 모델 업그레이드** | `microsoft/TRELLIS.2` 백엔드 추가(공개 Space로 먼저). 대체 경로 순서 구현. 입력 이미지 해시로 결과 캐시 | 같은 입력으로 v1과 v2를 나란히 비교할 수 있음. Space 하나가 막혀도 결과가 나옴 |
| **3. 후처리** | `trimesh`로 중심·크기 정규화, 바닥 정렬, 폴리곤 수 옵션(저·중·고) | 결과 모델이 항상 같은 크기와 방향으로 뷰어에 뜸 |
| **4. 자체 ZeroGPU Space** | TRELLIS.2와 스타일 변환을 우리 Space 2개로 배포. **RunPod 계획의 워커 API 형식을 그대로 사용** | 공용 Space 없이 동작. 나중에 RunPod로 옮길 때 MCP 쪽 코드는 그대로 |
| **5. 품질 루프** | ADK `LoopAgent`로 Critic 추가. 3D 미리보기 영상의 프레임을 원본과 비교해 점수가 낮으면 seed를 바꿔 **1회만** 재시도 | 테스트 세트에서 실패작 비율이 줄어듦 |
| **6. 스타일 LoRA** | Kaggle에서 SDXL LoRA 학습 → HF Hub에 업로드 → Space #2에서 로드 | 스타일 프리셋("우리 스타일")이 UI에 추가됨 |
| **7. UX** | 진행률, 원본과 3D 비교, 기록 저장, seed 재생성, `.glb`·`.obj` 내보내기 | 시중 서비스와 같은 흐름으로 쓸 수 있음 |

**0단계는 서둘러야 합니다.** 나노 바나나가 종료되면 지금 코드의 정제 단계가 에러를 냅니다. 에이전트가 에러를 받으면 정제를 건너뛰고 계속하도록 만들어 두긴 했지만, 매번 실패한 호출을 거치게 됩니다.

**4단계 전제 조건:** HF 계정이 가입 30일 이상이고 이메일 인증이 되어 있어야 합니다. 조건이 안 되면 그동안은 2단계의 공개 Space로 운영합니다.

## 시중 서비스와 비교해서 측정하는 방법

"시중 수준"을 감으로 판단하지 않고 숫자로 비교합니다.

- **테스트 세트 20장:** 사진 5장, 일러스트 5장, 손그림 스케치 5장, 캐릭터 5장
- **지표**
  - 성공률 (glb가 정상적으로 나온 비율)
  - 1건당 걸린 시간
  - 형태 충실도: Gemini 채점 1~5점 + 사람 채점
  - 텍스처와 색 충실도: 1~5점
  - 폴리곤 수와 파일 크기
- **비교 대상:** 같은 20장을 Tripo나 Meshy의 무료 크레딧 범위 안에서 생성. 무료 플랜 결과물의 사용 조건(저작자 표시 등)은 각 서비스 약관을 확인
- **목표:** 성공률 90% 이상, 형태 충실도 평균 4점 이상, 1건 2분 이내

## 무료로는 안 되는 것

| 한계 | 가장 싼 해결책 |
|---|---|
| 하루 수십 건 이상, 여러 사용자 동시 사용 | HF PRO(하루 40분, 월 9달러 수준) → 그 이상은 [RunPod 계획](../README.md#runpod-자체-호스팅-전환-계획) |
| 응답 시간 보장 | 전용 GPU (유료) |
| 리깅, 애니메이션 | 이 계획 범위 밖. Blender 자동 리깅이나 Mixamo로 후처리 |
| 게임용 쿼드 토폴로지 품질 | Blender 리메시로 비슷하게는 가능하지만 전문 도구 수준은 아님 |
